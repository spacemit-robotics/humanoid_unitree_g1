# 离线提示音

`operator_audio` 订阅 HMI 状态，在独立进程中调用播放器；
控制和推理线程不合成、不加载音频、不等待播放。仿真启动器默认静音。
WAV 文件由使用方按许可单独提供，文案清单见 `resources/audio/prompts.json`。
推荐格式为 PCM S16_LE、48 kHz、双声道，音色不限。

## 生效表

| 本次服务及反馈就绪、无锁存故障 | 程序已启动 |

| 配置中的手柄输入设备连接、身份匹配 | 手柄已连接 |
| 已连接的手柄输入设备断开 | 手柄已断开 |
| 手柄／网页等客户端实际获得控制权 | 已接管控制权 |

| 实际进入 POWER_OFF | 已掉电 |
| 实际进入 DAMP | 阻尼模式 |
| 走跑运控成功进入 RL，或 RL 内成功切入走跑 | 走跑模式 |
| 越障运控成功进入 RL，或 RL 内成功切入越障 | 越障模式 |
| 舞蹈运控成功进入 RL，或 RL 内成功切入舞蹈 | 舞蹈模式 |
| 控制权持有者切换快／慢档 | 快速模式／慢速模式 |
| 握手实际开始 | 你好啊 |
| 高举挥手实际开始 | 大家好啊 |
| 胸前挥手实际开始 | 很高兴见到你 |
| 飞吻实际开始 | 送你一个飞吻 |
| 鼓掌实际开始 | 太棒了 |
| 律动 1–4 实际开始 | wooo~ → 配置的律动配乐 |
| 新的控制故障锁存；未清除时每 15 秒重复 | 程序出现故障 |

HOME、ZERO 均不播，两套常规运控已从当前配置移除；不再有通用的 RL 播报。
只选择策略、模型准备中、切换被拒绝、同一状态重复上报均不播。
双 MNN 内部站走路由不播。网页/App 共用服务事件，TUI 的 FSM/动作也按实际状态播报。
快慢档属于网页/App 的客户端速度预设；TUI 单独输入速度不算换档。
重复点击当前档位、自动恢复默认慢档均不播换档提示。
控制权提示按服务确认的全局 `owner` 变化触发，与网页/手柄的按键实现无关；
只打开页面、接管失败、正常续租均不播。直接换持有者只播一次新接管，
音频观察器初次连接或重连不重播已有控制权，状态离线本身不伪造释放。

启动时不重复播 POWER_OFF。已有锁存故障只播故障，不播就绪。
新故障立即播一次；故障仍锁存时，每 15 秒重复同一条“程序出现故障”。
间隔由 `audio_prompts.fault_repeat_interval_s` 配置，清除锁存或状态失联即停止待播/正在播放的故障提示。
计时在独立音频进程中完成，不改变故障确认和控制链路。网络波动、手机离开、
重新连接不是“程序重启”，也不据此伪造低电量或遥控器 STOP 语音。

手柄连接提示复用 `operator_gamepad.device/vendor/product`，不把 USB 接收器本体插入、
接管/释放控制权或网页连接当作手柄连接。设备文件身份校验通过后播连接；
设备撤销或返回挂断/错误时播断开，同一状态不重复。启动时没有手柄保持安静，
启动时已连接则播一次连接。音频观察器重连 HMI 不重置这份连接状态。
仅只读打开输入设备、校验身份并检查挂断，不读取按键、不独占设备、不操作蓝牙配对。
使用现有音频进程的 50 ms 轮询，待设备出现时每秒重试打开；手柄静止不算断开。
播报在 HMI 状态在线时运行；不改手柄失联清零和控制权释放逻辑。

## 播放配置

`audio_prompts.player` 指定播放器和声卡，例如 `aplay --quiet --device=plughw:CARD=Device,DEV=0`。
部署时检查实际 ALSA 设备名并配置默认音量，控制循环不修改混音器。
提示队列最多 4 条，超时 3 秒丢弃，普通语音最长 5 秒，配乐最长 30 秒。
故障和掉电提示优先，可中断旧音频；播放失败不关闭控制进程。

舞蹈可配置 `prefix` 和 `music`，前奏结束后播放配乐，不延迟机器人动作。
动作完成、取消、退出 RL 或状态失联时停止音乐。四段可以共用一首配乐，
也可在 YAML 中分别指定文件；不要求音频时长与动作完全相等。
模型、音色和第三方媒体的许可独立于 SDK 源码许可证。
